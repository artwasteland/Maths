Design and use
  Priority is SEED order, then physical file order; unknown never wins. Gzip
  streams are decoded once. An immutable scratch spool holds admitted candidate
  bytes, with alternative offsets in SQLite and compact graph metadata in RAM.
  Original compressed seed bytes are SHA-256 hashed below decompression, including
  skipped lines. Bundle summary.json is never read. One file handle is consumed
  at a time. Scratch disk can grow to the total admitted candidate bytes; use
  --scratch to choose its parent. No symbolic algebra or producer is imported.

  Reverse reachability from direct records finds every graph with a structurally
  grounded alternative. Choose its earliest usable record. Detect selected cycles
  iteratively. For each cycle, try members in input order and alternatives in seed
  order, searching for a simple path to a root that avoids the cycle. Apply the
  whole escape path only after finding it. This also handles alternatives whose
  targets need replacement. Unrooted cycles and their dependents become UNKNOWN.
  The repair stack contains IDs, not live SQLite cursors. Events stream from SQLite
  into assembly.json. Its unresolved events describe seed selection before any
  optional propagation, which can subsequently decide such a graph.

  --propagate is opt-in; --no-propagate explicitly disables it. It reads and hashes
  the pipeline index's 19-byte parent/child/11-label rows and both adjacency
  directions, without importing the pipeline. Format/map orientation:
  research/gp-11/pipeline/poset.py:7,32-37,70-78. Embedded records propagate down
  via super; refuted records propagate up via sub. New pointers refer to already
  selected records. Propagation stays within INPUT, using exact outside hosts
  where available. It does not traverse through new outside-input pointer records.
  Both directions and their actual maps were tested with the frozen checker.

  records.jsonl contains selected decisions in INPUT order. UNKNOWN.g6 contains
  the complement in INPUT order. unknown-records.jsonl supplies explicit unknown
  records with assembly-only budgets; hosts.jsonl contains needed exact hosts.
  All four files exist even when empty. assembly.json includes input and seed
  hashes, counts by verdict/source, skip reasons, replacements, broken cycles,
  unresolved dependencies, payload hashes, and these required manifest fields:
    "records": ["records.jsonl", "unknown-records.jsonl"],
    "hosts": "hosts.jsonl", "unknown": "UNKNOWN.g6"
  Its run_fields also supplies input and input_sha256. The caller adds profile,
  controls and predictions. A manifest's own digest cannot be stored inside its
  own bytes; assembly.json.sha256 hashes assembly.json. The checksum receipt
  itself is not recursively self-hashed. All certificate/list outputs are hashed.
  Output is staged and published only on success, into a new or empty directory.

  --check re-reads the physical streams, checks uniqueness, input order, exact-only
  hosts, dependency presence/verdict, cycles, line limits, and both UNKNOWN files.
  It does not trust reported counts or check geometry, canonical labels, maps or
  algebra. It prints STRUCTURE OK / STRUCTURE ERROR, never checker verdict lines.
  --input defaults to frozen B11.g6 in BOTH modes; specify it for sample checks.

Rewrite design
  Only an unindexed refuted sub pointer or a refuted TU end.refuted with an
  outside target that has a refuted seed claim is eligible. Unknown, embedded,
  indexed, direct and inside-input records retain their original bytes.
  Alternatives keep their original candidate IDs and seed/file priority.
  Each distinct D is searched once. Necessary vertex, edge and sorted-degree
  filters skip impossible patterns without reordering F10. VF2 visits sorted
  labels/edges. The FIRST matching original index wins. Search is limited to
  2,000,000 feasibility attempts per D, order 64 and 10,000 cached targets.
  A bound is reported as a bound, never as a claim that D is F10-free.

  For TU the new map is m[phi[j]] in stored pattern order. For indexed sub the
  checker supplies the canonical code; an exact isomorphism from that decoded
  canonical graph to the stored pattern recovers the label correspondence.
  The checker exposes no nauty permutation. This is not another canonicalizer:
  any isomorphism to the frozen canonical graph differs only by an automorphism
  and gives an equally valid edge map. The map is m[phi[canonical_to_stored[j]]].
  The sub fixture deliberately uses F10 index 2, whose stored/canonical labels
  differ, and the frozen checker judges the resulting pointer.

  in_force(idx) is called before replacement; an unavailable index aborts before
  output publication. No match prints REWRITE UNRESOLVED, records the reason,
  and leaves the original unresolved dependency for the existing selection
  logic. The graph stays UNKNOWN unless another usable candidate exists.
  assembly.json records graph, D, idx, phi, rule, source, candidate ID, original
  and rewritten line SHA-256 (newline included), and whether it was selected.
  Indexed sub receipts also include the canonical code and label conversion.
  All candidate rewrites are recorded, including unused agreeing alternatives.
  Outside refuted support records remain omitted. --check is still structural.

Live-state snapshot and memory
  The state directory is accepted as a positional SEED. accepted JOIN blobs
  metadata is copied under one read transaction into scratch SQLite and an
  output seed-0-snapshot.jsonl. The transaction then closes before containment
  search. No Store object, writer lock, database backup or checkpoint is used.
  The original certificates.jsonl is opened rb. Each accepted row is checked
  against its stored g6/verdict/dep, blob size and SHA; selected blobs are read
  again and rehashed when written. Original certificate bytes never enter the
  scratch spool; only rewritten lines do. A fixture appends a committed record
  after capture and proves it is excluded while the original output still
  passes the frozen checker. The fixture also asserts an empty initial spool.

  State receipts contain the logical metadata SHA, capture time, max seq, row
  count, origins, and SHA of the committed certificate prefix [0, bytes).
  Appends beyond that prefix are permitted. No whole-file hash is claimed for
  the changing live SQLite/WAL files. The metadata sidecar is an output file
  with its own hash. All other output hashes and the detached assembly.json
  checksum follow round 1. Per-graph state remains IDs, verdicts, dependencies
  and offsets; certificates are not held in an in-memory population list.
