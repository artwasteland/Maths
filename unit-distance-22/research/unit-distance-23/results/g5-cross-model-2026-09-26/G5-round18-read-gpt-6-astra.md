## The context

The project asks for u(23): the largest number of pairs at distance exactly 1 among 23 points in the plane (the
"unit distance" problem; the known values stop at u(21) = 57, in a recent paper by Alexeev, Mixon and Parshall). Our
position is that u(23) is 64 or 65. To decide it we enumerated, by computer, every graph structure that could realise
65 unit distances on 23 points. The work was split into 1,920 slices; each slice is one run directory produced by a
committed runbook. Every graph in the enumeration is either pruned with a certificate, an exact algebraic reason it
cannot be drawn with unit edges, or kept. Only one graph was kept at the top level, in slice 50, and it is refuted by
an exact certificate that two independent verifiers accept. If every gate of research/unit-distance-23/CONTRACT.md is
green, the write-up (research/unit-distance-23/RESULT-u23.md, generated by tools/write_result.py) will say u(23) = 64.

A computer proof is only as trustworthy as the checks run on its output, so the project has a chain of checking
scripts. They read the enumeration's output files and decide whether the files are complete and consistent. This
review is about those checking scripts. The question is whether each one would notice a mistake in the files it
reads: a missing cell, a wrong count, a sampled cross-check that covered less than it claims, or a slice whose shared
first levels were never cross-checked. It is a correctness review of our own scientific software, and nothing in it
involves any system beyond this checkout and its data files.

Three kinds of evidence are judged:
- The (23,65) run itself. Its sampled cross-check, "G4", re-derives a seeded sample of each cell's children with an
  independent enumerator.
- Two control runs through the same pipeline: (22,61), which must find nothing, and (21,57), which must find all
  five known extremal graphs.
- A full re-run of every slice, each run directory checked by the reviewed checker.

This is the eighteenth review round. The questions, findings and our written responses of each round are in
research/unit-distance-23/results/g5-cross-model-2026-09-26/, files G5-round10-read-gpt-6-astra.md to
G5-round17-read-gpt-6-astra.md. Round 17 found six MAJOR problems and one MINOR problem. Its Response section says
how each was fixed (commit fd01053593).

One more thing is new since round 17. The full re-run found that the reviewed checker needs more memory than a
15 GB cloud worker on the heaviest slices: six checks were stopped by the kernel for lack of memory before they
printed anything. So there is now a memory-bounded copy of the checker (commit 4216d6a5a5):
- research/unit-distance-22/enum/verify-chain-lean.py. It is research/unit-distance-22/enum/verify-chain.py with
